# ADR-001: Adopt Astro for the Atlantic Fieldnotes Website

- Status: Accepted
- Date: 2026-10-28

## Context

The project is a personal and editorial website for Atlantic Fieldnotes, an evolving field guide to birds and birding places along Ireland’s western shore. The site needs to present static content, long-form article pages, photography-heavy layouts, and relatively simple publishing workflows without requiring a large application framework or custom backend.

I wanted a content-first approach with good performance, straightforward deployment, and the ability to keep content and presentation maintainable as the site grows. A lightweight static site generator is a strong fit, especially for a publication-style website that may expand to include more essays, photo essays, and reference pages over time.

## Decision

We will use Astro as the primary framework for building and deploying the Atlantic Fieldnotes website.

This decision includes:

- Using Astro for static site generation and page routing.
- Storing article content in Markdown-based content collections.
- Using Astro components for reusable page structures and metadata.
- Serving the site as static files through a CDN/static hosting model.
- Keeping the architecture simple and maintainable for a content-driven site.

## Rationale

Astro is well suited to this project because it balances editorial simplicity with modern web performance. It allows the site to render lightweight static pages while still supporting component-based design patterns. The project does not currently require a complex server-side application, so a static-first architecture reduces operational cost and maintenance overhead.

Astro also supports the content model needed for a field guide and blog-style site:

- Markdown-based article authoring.
- Flexible frontmatter for metadata such as title, date, and tags.
- Reusable layouts and components for consistent presentation.
- Efficient static output suitable for CloudFront/S3 hosting.

This choice keeps the site fast and easy to deploy while preserving room for future enhancements such as additional article collections, richer media display, or expanded navigation.

## Consequences

### Positive

- Excellent performance for static content.
- Simple publishing model for articles and pages.
- Good support for photo-heavy layouts and content collections.
- Easy deployment to static hosting infrastructure.
- Clear separation between content, layout, and styling.

### Negative

- Some dynamic web features would need separate implementation if they are added later.
- A static architecture may be less suitable for highly interactive or database-driven features.
- Content authoring requires familiarity with Markdown and frontmatter conventions.

## Follow-up

This decision should be revisited if the project grows into a CMS-backed or highly interactive platform, or if dynamic data requirements become central to the experience.
